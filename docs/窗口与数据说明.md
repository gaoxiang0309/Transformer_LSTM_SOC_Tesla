# 数据、行车状态、因果窗口与划分（Tesla Model 3 2170）

本轮只做**行车状态**SOC。状态划分依据是“充电事件/文件类型”，不是电流符号；行车内部（放电、回馈、短停车）整体保留。

## 1. 原始数据与时间清洗

来源：McMaster University 的 Tesla Model 3 2170 开放数据（Blind Modeling Tool V3）：

```text
解压数据与工具/
├── m80/       # Ch1，训练电芯
├── m448-N/    # Ch3，验证电芯
└── m1000/     # Ch4，测试电芯
    └── <温度>/Drive Cycles/*.mat
```

每个 MAT 是 `meas` 结构，含 `Time / Voltage / Current / Battery_Temp_degC / SOC` 等列。README 称已重采样到 1 Hz，但**原始 Time 并非严格 1 Hz**：6 个行驶文件存在亚秒级重复突发（时间差小到 4e-5 s），共 44,271 行；其中两处最大：m448-N 40℃ REORDERED1（23,876 行）和 m1000 40℃ HWGRADE1（19,762 行）。这些行会让“按行号当 1 秒”的窗口和安时积分严重失真。

本项目的处理规则：

- **只保留行驶文件**：`REORDERED1–8`、`HWCUST1`、`HWGRADE1`；`CC_CV_charge` 充电文件整体排除（本轮不做充电SOC）。
- **按 Time 重采样到约 1 Hz**：保留第一个点，之后与上一个保留点时间差 `≥0.5 s` 才保留，压掉亚秒级重复突发。
- **切缺口**：相邻保留点时间差 `> max_gap_seconds=60 s` 时切开序列，窗口不跨缺口。
- **长驻车切分**：文件内连续静置（`|I| ≤ 0.05 A`）超过 `max_parking_seconds=1800 s` 时，把该静置段从序列中切掉，前后各成一条序列（命名加 `_p1/_p2`）；短停车保留。
- 片段起点因历史不足的前缀没有输出：`L+K-2 = 358` 点（358 s），不补零、不借用其他片段历史。

清洗后全数据共 180 条序列：训练 60 条 1,208,237 点，验证 60 条 1,362,581 点，测试 60 条 1,072,901 点；重采样共删除 44,271 行。

## 2. 输入和标签

- 输入四维：**V、I、T、Ah**（`Voltage / Current / Battery_Temp_degC / Ah_integral`），模型输入 `[B,L,4]`。
- Ah 是安时积分：`Ah[t] = ∫_{0}^{t} I dτ / C_nom`，其中 `C_nom=4.5 Ah`，单位是额定容量的比例；每条序列从 0 开始，用真实时间差积分。正电流（回馈/充电）使 Ah 增加，负电流（放电）使其减小。**Ah 只由电流得到，不读取真实 SOC。**
- 标签为窗口末端时刻的 SOC（0～1），只用于监督和评价，不进入特征。
- 物理锚：`anchor[t] = (q[0] - a(T)·Ah[0]) + a(T)·Ah[t]`，其中 `a(T)=4.5/C(T)`，C(T) 由 m80 训练集按温度拟合（−20℃ 4.209、−10℃ 4.241、0℃ 4.284、10℃ 4.361、25℃ 4.479、40℃ 4.583 Ah）。q[0] 是段首第一个初估，用它反推段首 SOC；输出用双支路混合 `α·anchor+(1−α)·q+残差`（`anchor_mode=dual`，α 初始化≈1），残差/混合比例负责修正初值偏差。
- 短窗 ΔAh：`ΔAh_K[t]=Ah[t]-Ah[t-K+1]`、`ΔAh_L[t]=Ah[t]-Ah[t-L+1]`，直接给 LSTM 近期电荷吞吐。
- 注意：官方 README 的提交接口写 `[Current, Voltage, Temperature]`，但官方切好的数据实测是 `[Voltage, Current, Temperature]`；本项目从原始 MAT 读取，直接按 V/I/T 排列，并在其后拼接 Ah。

## 3. 窗口按物理秒定义

- 长窗 `long_window_seconds=300 s`，短窗 `short_window_seconds=60 s`；`sample_interval_s=1.0`，因此换算为 **300 点 / 60 点**。
- 换采样率时只改 `sample_interval_s`，点数由 `validate()` 自动换算（例如公司 3 s/帧时，300 s≈100 点、60 s≈20 点）。
- 两级完整模型依赖 `L+K-1 = 359` 个原始点，首个最终输出在 `L+K-2 = 358`。
- 窗口因果：结束于当前时刻 `t`，不读未来；不跨文件、不跨缺口、不跨长驻车切分边界。

## 4. 归一化

V/I/T 只用训练划分（m80）拟合 `robust_minmax`；Ah 使用固定物理范围，避免测试段深放电/回馈被训练分位数截断：

```text
low = percentile(x_train, 0.01)    # V/I/T
high = percentile(x_train, 99.99)
x_norm = (clip(x, low, high) - low) / (high - low)
# Ah: low=-1.2, high=0.2（额定容量比例），固定，不随训练集变化
```

| 通道 | low | high | 训练截断 | 验证截断 | 测试截断 |
|---|---|---|---|---|---|
| V | 2.7998 V | 4.2010 V | 0.02% | 0.03% | 0.03% |
| I | −9.2269 A | 7.5421 A | 0.02% | 0.11% | 0.60% |
| T | −20.178 ℃ | 44.607 ℃ | 0.02% | 0.05% | 0.12% |
| Ah | −1.2 | 0.2 | 0.00% | 0.00% | 0.00% |

用 p0.01 而不是 p0.1 的原因：行车数据电流尾部较窄，p0.1 会让 m1000 约 3% 的高电流样本饱和；p0.01 把测试饱和降到约 0.6%，同时仍剔除极端离群点。参数写入 `manifest.json` 的 `normalization` 字段，**不允许在验证/测试上重新拟合**。

## 5. 划分

| 集合 | 电芯 | 序列 | 点数 | 说明 |
|---|---|---|---:|---|
| train | m80（Ch1） | 60 | 1,208,237 | 6 个温度 × 10 个行驶循环 |

| test | m1000（Ch4） | 60 | 1,072,901 | 只在训练完成后读取 |

三个集合来自不同电芯，不共享任何原始文件；但同一批电芯来自同一台架与同一套 SOC 计算流程，不能宣称独立车辆验证。

## 6. 数据组成（行车内部）

按相邻 SOC 变化分类：

| 集合 | 静置/短停车 | SOC 上升（回馈） | SOC 下降（放电） |
|---|---:|---:|---:|
| 训练 | 9.0% | 20.1% | 70.9% |
| 验证 | 14.7% | 25.0% | 60.3% |
| 测试 | 9.1% | 23.9% | 67.0% |

回馈、0 A、短停车都属于行车，不再切子状态。

## 7. 两阶段时刻定义

```text
q[s] = Transformer( x[s-L+1 : s+1] )   # x为[V,I,T,Ah]
anchor[s] = (q[0] - a(T)·Ah[0]) + a(T)·Ah[s]
fused[s] = [x[s], q[s], anchor[s], ΔAh_K[s], ΔAh_L[s]]
residual[t], α[t] = LSTM( fused[t-K+1 : t+1] )   # α为dual混合比例
y_hat[t] = α[t]·anchor[t] + (1−α[t])·q[t] + residual[t]   # anchor_mode=dual
监督目标 = y[t]
```

实验三可在融合列末端追加四个因果历史统计。它们按完整序列计算后再裁切，列顺序为
`V_mean_60`、`I_mean_60`、`V_dev_60`、`I_dev_60`。其中
`V_dev_60=V_t−V_mean_60(t)`，`I_dev_60=I_t−I_mean_60(t)`。
统计值沿用V/I通道的训练侧仿射归一化尺度，序列开始处使用已有历史的截短均值。

- Transformer 首个 q 的索引：`L-1 = 299`。
- LSTM 首个最终输出索引：`L+K-2 = 358`。
- `make_fused_sequences()` 逐窗口生成 q（stride=1），不会把不相邻时刻拼成短窗。
- 锚的斜率 `a(T)` 与 Ah 的变化精确匹配；`anchor` 的误差主要来自 q[0] 的初值偏差，由 gated 门控与 LSTM 残差共同修正。

## 8. 评估对齐与覆盖率

`test.py` 先为每个测试序列生成 q，再构造短窗；在**同一目标时刻**比较 `q[t]` 与 `y_hat[t]`。`metrics.json` 记录：

- `state_filter="driving_only"`、`window_seconds`、`sampling_interval_s`、`first_valid_local_target=358`；
- 原始加载点数、输出窗口数、`stride`；
- `coverage_ratio = prediction_windows × stride / raw_points`，反映冷启动、缺口与长驻车切分造成的无输出范围；
- `predictions.csv` 保留 `source_row`（原始文件行号）。

指标单位为百分点，不裁剪预测。
